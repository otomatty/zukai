# 構造が崩れた資料

## 配信の流れ

配信サーバは記事を受け取ります。その後、配信サーバは記事を変換します。

配信の前に、記事の形式を確認します。

```yaml figure
type: flow
steps:
  - label: 受信
  - label: 変換
  - label: 配信
```

```yaml figure
type: flow
steps:
  - label: 確認
  - label: 記録
```

配信サーバは、受信した記事をHTMLに変換します。変換に失敗した記事は、配信サーバが失敗キューに入れます。失敗キューに入った記事は、担当者が翌営業日に原因を確認します。原因が形式の誤りだった場合、担当者は記事の作成者に修正を依頼します。原因が配信サーバの不具合だった場合、担当者は開発チームに調査を依頼します。開発チームは、調査の結果を3営業日以内に担当者へ報告します。担当者は、報告の内容を記事の作成者へ伝えます。
