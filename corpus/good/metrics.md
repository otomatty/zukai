# ログイン機能の計測結果

この資料は、ロックの導入とセッションDBへの移行について、導入前後の計測結果を説明します。

## 応答時間の変化

ログイン要求の平均応答時間は、移行後に110ミリ秒へ短くなりました。

```yaml figure
type: bar
unit: ミリ秒
items:
  - label: 移行前
    value: 180
  - label: 移行後
    value: 110
    emphasis: true
```

計測の対象は、平日9時から10時のログイン要求です。移行前は10月5日、移行後は10月26日に計測しました。

## ログイン失敗の件数

パスワード誤りによる失敗は、ロックを導入した8月から減りました。

```yaml figure
type: line
unit: 件／月
x: [5月, 6月, 7月, 8月, 9月, 10月]
series:
  - label: パスワード誤り
    values: [320, 340, 330, 210, 150, 120]
  - label: ロック中の試行
    values: [0, 0, 0, 90, 60, 40]
  - label: 期限切れ
    values: [60, 55, 70, 65, 58, 62]
marker:
  at: 8月
  label: ロックを導入
```

ロック中の試行は、ロックされた利用者が解除の前にログインを試みた回数です。期限切れによる失敗は、ロックの導入前後で変わっていません。

## 月ごとの利用者数

管理画面の利用者は、半年で1,480人まで増えました。

```yaml figure
type: line
unit: 人
x: [5月, 6月, 7月, 8月, 9月, 10月]
series:
  - label: 利用者数
    values: [920, 1010, 1130, 1250, 1390, 1480]
```

利用者数は、その月に1回以上ログインした利用者を数えています。
