# 返答を図解の資料にする

説明が必要な返答は、チャットの外に図解の資料として書きます。チャットには、結論と資料の場所だけを書きます。

## 資料にする返答

- 説明、設計、比較、手順の説明を求められたとき
- 利用者に図解を頼まれたとき
- 作業の報告で、変更点が多いとき

短い質問の答えと、コードを直す作業の途中は、資料にせずにチャットで答えます。

## 手順

1. `{{zukai}} view` を実行します。表示用のページが動いていなければ起動し、初回はブラウザで開きます。出力された URL を控えます。
2. `{{zukai}} prompt --type-command='{{zukai}} type'` を実行し、出力された書き方に従います。使う型を決めたら、出力にあるコマンドで型の書き方を確認します。
3. 原稿を `.zukai/answers/<年月日>-<時分>-<英小文字とハイフンの名前>.md` に書きます。例は `.zukai/answers/20261010-1530-auth-flow.md` です。
   - `#` の題名には、依頼を1行にまとめて書きます。
   - 題名の直後の段落に、依頼の文、日時、ツールとモデルの名前を書きます。
   - 題材にない主体、数値、原因は足しません。コード参照には、自分で開いて読んだファイルと行だけを書きます。
4. `{{zukai}} lint <原稿のパス> --model=<自分のモデル名>` を実行し、error をすべて直します。warn は、具体的に書き直せる場合だけ直します。直すときは、指摘された箇所だけを変えます。
5. 手順4は2回までです。2回直しても error が残る場合は、原稿をそのまま残します。残った指摘は、表示用のページが本文の上に出します。警告を消すためだけの言い換えは行いません。
6. 手順2の出力に「動画の書き方」がある場合は、動画も作ります。書き方に従ってナレーションとシーンを足したら、手順4と同じ Lint を最終の原稿に対してもう一度実行し、error を直します。ナレーションも、用語の表記（P007）などの検査を受けるためです。そのあと `{{zukai}} frames <原稿のパス> --sheet` で確かめてから、`{{zukai}} video <原稿のパス>` を実行します。
7. チャットには、結論を1文、資料の URL、原稿のパスを書きます。動画を作った場合は、MP4 のパスも書きます。Lint（動画を作った場合は、手順6の最終の原稿に対する結果）と動画の検査の指摘が残った場合は、その件数も書きます。図の YAML はチャットに書きません。

## zukai が動かないとき、設定を変えるとき

- コマンドが設定の誤りや足りないもので止まったら、`{{zukai}} doctor` を実行し、✘ と ! の項目と、表示された直し方を利用者に伝えます。設定ファイルを推測で書き換えません。
- 利用者に設定を変えるよう頼まれたら、`{{zukai}} config set <項目> <値>` を使います。チームの設定（`zukai.config.json`）に書くか、自分だけ（`--scope=local`）にするかは、利用者に確かめます。項目の一覧は `{{zukai}} help config` にあります。
- API キーとトークンは、チャットで尋ねません。利用者に、自分の端末で `zukai login gemini` か `zukai login confluence` を実行するよう頼みます。
