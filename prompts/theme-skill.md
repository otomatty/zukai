# 資料からデザインのテーマを作る

zukai の図と動画の見た目は、テーマのフォルダで変えます。フォルダには2つのファイルを置きます。

| ファイル | 内容 | 使われ方 |
|---|---|---|
| `tokens.json` | 色、フォント、線の太さ、コードの配色 | 資料（HTML、Confluence の PNG）と動画の図を描くときに使う。自由な図に使える色も、この値で決まる |
| `rules.md` | 描き方のルール | `zukai prompt` が AI への指示に入れる。「## 動画」の節は、動画を作るときだけ入る |

値はあなたが資料から決めます。正しいかどうかは `{{zukai}} theme check` が確かめます。

## 手順

1. 取り込む資料を確かめます。利用者が資料を渡していなければ、尋ねます。Claude Design などのデザインツールで作ったものは、書き出した HTML や CSS、Claude Code に引き渡されたファイル、PDF のどれかで受け取ります。資料と動画のどちらの見た目をそろえたいかも確かめます。
2. `{{zukai}} config get theme` を実行します。テーマがすでに設定されていれば、そのフォルダを直します。無ければ `{{zukai}} theme init <フォルダ>` でフォルダを作ります。フォルダの名前は、利用者に指定がなければ `zukai-theme` にします。
3. 資料を読み、値を集めます。ファイルに書かれた値を、見た目からの推定より優先します。
   - HTML、CSS（Claude Design の書き出しなど）: CSS 変数（`--color-primary` など）、`color`、`background`、`font-family` の値を読みます。
   - PowerPoint（.pptx）: zip を展開し、`ppt/theme/theme1.xml` の `a:clrScheme`（`dk1`、`lt1`、`dk2`、`lt2`、`accent1`〜`accent6`）と `a:fontScheme`（`latin` と `ea` の書体）を読みます。
   - PDF、画像: ページを画像として見て、色を読み取ります。推定した値は、手順5で「出典」に推定と書きます。
   - Web ページ: ページの CSS を読みます。
4. `tokens.json` の値を、役割に合わせて書き換えます。資料に見当たらない値は変えません。
   - `color.ink` は本文と図の文字、`color.sub` は補足の文字、`color.paper` は背景、`color.surface` は箱の地色、`color.line` は枠線、`color.accent` は強調、`color.accentSurface` は強調した箱の地色、`color.onAccent` は強調の色の上に載る文字です。
   - `chart.series` はグラフの系列の3色です。資料のアクセントの色から、明るさか色相が離れた3色を選びます。
   - `font` は、資料の書体を先頭に書き、今ある日本語の書体を後ろに残します。HTML は書体を埋め込まないので、読む人の PC に無い書体は、後ろの書体で表示されます。
   - `codeTheme` は Shiki の配色の名前です。背景を暗くしたときは `github-dark` のような暗い配色にします。
   - 動画の背景（`video.background`）を変えたときは、`video.ink`、`video.subtitle`、`video.figure.color`、`video.figure.chart` も、その背景に合わせてまとめて変えます。
   - `video.palette` の12色は、名前が色相を表しています。名前は変えず、それぞれ資料の中で近い色相の色に置き換えます。
   - 図の幅と動画の大きさ（`figure.width`、`video.width`、`video.height`、`video.fps`）は変えられません。
5. `rules.md` を書きます。
   - `#` の見出しはテーマの名前です。`## 図` に自由な図の描き方を、`## 動画` に動画のシーンの絵柄を、`## 出典` に読んだ資料の名前と、そこから決めた値を書きます。
   - 資料に見られる描き方だけを、確かめられる形で書きます。例: 「角丸は使わず、四角は直角にする」「強調は1つの図に1か所だけにする」「背景は白地にし、キャラクターは描かない」。「洗練された印象にする」のような、確かめられない書き方はしません。
   - 色は `accent` のように役割の名前で書きます。色の値は `tokens.json` にだけ書きます。
   - 原稿の書き方（文字数、図の型、検査）と食い違うルールは書きません。食い違う場合は、原稿の書き方が優先されます。
6. `{{zukai}} theme check <フォルダ>` を実行し、error をすべて直します。直すときは、色相を保ったまま明るさを変えます。warn は、資料の色から大きく離れずに直せる場合だけ直します。値を変えたら、元の値と変えた理由を `rules.md` の「出典」に書きます。
7. `{{zukai}} theme preview <フォルダ>` を実行し、書き出された HTML を資料と見比べます。HTML や画像を見られない場合は、利用者にブラウザで開いてもらい、気になる点を尋ねます。直したら、手順6からやり直します。見比べて直すのは2回までです。
8. テーマを使う設定をします。チームで共有するか（`zukai.config.json` に書き、フォルダもコミットする）、自分だけにするか（`--scope=local`）を利用者に確かめてから、`{{zukai}} config set theme <フォルダ>` を実行します。
9. チャットには、テーマのフォルダ、見本の HTML のパス、主な値をどの資料から取ったか、手順6で変えた値、残った warn を書きます。

## 守ること

- 資料そのものは、テーマのフォルダにコピーしません。テーマをコミットしたときに、社外秘の資料がリポジトリに入らないようにするためです。「出典」には資料の名前だけを書きます。
- 資料の文章を `rules.md` に写しません。書くのは描き方のルールだけです。
- テーマを変えると、自由な図（`svg figure`）に書いた前の色は、Lint の F001 になります。利用者が既存の原稿を使い続ける場合は、そのことを伝えます。
- `{{zukai}} theme check` が値の誤り（無い項目、色でない値）で止まったら、`tokens.json` を直します。項目の一覧は、`{{zukai}} theme init` で作った `tokens.json` にあります。
