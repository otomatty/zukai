# 資料からデザインのテーマを作る

zukai の図と動画の見た目は、テーマのフォルダで変えます。フォルダには次のファイルを置きます。

| ファイル | 内容 | 使われ方 |
|---|---|---|
| `tokens.json` | 色、フォント、グラデーション、強調の描き方、グラフの色の付け方、線の太さ、コードの配色 | 資料（HTML、Confluence の PNG）と動画の図を描くときに使う。自由な図に使える色も、この値で決まる |
| `rules.md` | 描き方のルール | `zukai prompt` が AI への指示に入れる。「## 動画」の節は、動画を作るときだけ入る |
| `types/<名前>/` | テーマの独自の図の型（任意） | 組み込みの型と同じように、指示に出て、検査を通り、資料と動画に描ける |

値はあなたが資料から決めます。正しいかどうかは `{{zukai}} theme check` が確かめます。

## 手順

1. 取り込む資料を確かめます。利用者が資料を渡していなければ、尋ねます。Claude Design などのデザインツールで作ったものは、書き出した HTML や CSS、Claude Code に引き渡されたファイル、PDF のどれかで受け取ります。資料と動画のどちらの見た目をそろえたいかも確かめます。
2. `{{zukai}} config get theme` を実行します。テーマがすでに設定されていれば、そのフォルダを直します。無ければ `{{zukai}} theme init <フォルダ>` でフォルダを作ります。フォルダの名前は、利用者に指定がなければ `zukai-theme` にします。
3. 資料を読み、値を集めます。ファイルに書かれた値を、見た目からの推定より優先します。
   - HTML、CSS（Claude Design の書き出しなど）: CSS 変数（`--color-primary` など）、`color`、`background`、`font-family` の値を読みます。
   - PowerPoint（.pptx）: zip を展開し、`ppt/theme/theme1.xml` の `a:clrScheme`（`dk1`、`lt1`、`dk2`、`lt2`、`accent1`〜`accent6`）と `a:fontScheme`（`latin` と `ea` の書体）を読みます。
   - PDF、画像: ページを画像として見て、色を読み取ります。推定した値は、手順5で「出典」に推定と書きます。
   - Web ページ: ページの CSS を読みます。
4. `tokens.json` の値を、役割に合わせて書き換えます。資料に見当たらない値は変えません。
   - `color.ink` は本文と図の文字、`color.sub` は補足の文字、`color.paper` は背景、`color.surface` は箱の地色、`color.line` は枠線、`color.accent` は強調、`color.accentSurface` は強調した箱の地色、`color.onAccent` は強調の色の上に載る文字です。
   - `chart.series` はグラフの系列の3〜5色です。資料に系列の色の決まりがあれば、その順に書きます。無ければ、資料のアクセントの色から、明るさか色相が離れた3色を選びます。
   - 資料がグラデーションを使っていれば、`gradient.stops` に色を順に（2〜5色）、`gradient.angle` に向き（CSS の角度。90 は左から右）を書きます。
   - `emphasis.box` は強調した箱の描き方です。資料の強調の見せ方に近いものを選びます。`flat`（淡い面と強調の色の枠）、`fill`（グラデーションの面に白抜きの文字）、`tint`（淡いグラデーションの面とグラデーションの枠）、`outline`（グラデーションの枠）のどれかです。`fill` は、白抜きの文字がグラデーションのどの色の上でも読めないと、手順6で error になります。
   - `emphasis.chart` は、グラフで強調するものの塗り方です（`flat` か `gradient`）。
   - `chart.mode` は、資料のグラフが「灰色を基本にして、強調するものだけに色を付ける」なら `neutral`、項目ごとに色を変えるなら `series` にします。
   - `font` は、資料の書体を先頭に書き、今ある日本語の書体を後ろに残します。HTML は書体を埋め込まないので、読む人の PC に無い書体は、後ろの書体で表示されます。
   - `codeTheme` は Shiki の配色の名前です。背景を暗くしたときは `github-dark` のような暗い配色にします。
   - 動画の背景（`video.background`）を変えたときは、`video.ink`、`video.subtitle`、`video.figure.color`、`video.figure.chart` も、その背景に合わせてまとめて変えます。
   - `video.palette` の12色は、名前が色相を表しています。名前は変えず、それぞれ資料の中で近い色相の色に置き換えます。
   - 図の幅と動画の大きさ（`figure.width`、`video.width`、`video.height`、`video.fps`）は変えられません。
5. `rules.md` を書きます。
   - `#` の見出しはテーマの名前です。`## 図` に自由な図の描き方を、`## 動画` に動画のシーンの絵柄を、`## 出典` に読んだ資料の名前と、そこから決めた値を書きます。
   - 資料に見られる描き方だけを、確かめられる形で書きます。例: 「角丸は使わず、四角は直角にする」「強調は1つの図に1か所だけにする」「背景は白地にし、キャラクターは描かない」。「洗練された印象にする」のような、確かめられない書き方はしません。
   - 色は `accent` のように役割の名前で書きます。色の値は `tokens.json` にだけ書きます。
   - 原稿の書き方（文字数、図の型、検査）と食い違うルールは書きません。食い違う場合は、原稿の書き方が優先されます。
   - 資料に、組み込みの型に無い決まった図（主役の数字、決まった形のカードなど）があれば、手順5の後に「独自の型を作る」に従って型を足します。利用者に、型にするかを確かめてから作ります。
6. `{{zukai}} theme check <フォルダ>` を実行します。error と warn は、黙って直しません。資料の値を変えないと直らないものは、「対話で決める」に従って、案を見せて利用者に選んでもらいます。
7. `{{zukai}} theme preview <フォルダ>` を実行し、書き出された HTML を利用者に見せます。HTML や画像を見られない場合は、利用者にブラウザで開いてもらいます。利用者が見た目の変更を頼んだら、「対話で決める」に従って案を見せ、決まったら手順6からやり直します。
8. テーマを使う設定をします。チームで共有するか（`zukai.config.json` に書き、フォルダもコミットする）、自分だけにするか（`--scope=local`）を利用者に確かめてから、`{{zukai}} config set theme <フォルダ>` を実行します。
9. チャットには、テーマのフォルダ、見本の HTML のパス、主な値をどの資料から取ったか、手順6で変えた値、残った warn を書きます。

## 対話で決める

資料だけでは決まらないこと、検査と資料が食い違うこと、利用者が見た目の変更を頼んだことは、利用者と対話して決めます。あなたが1人で決めて、結果だけを伝えることはしません。

1. 決めることを1つずつ取り上げます。関係する値（強調した箱の描き方と、その文字の色など）は、1つの問いにまとめます。
2. 案を2〜3個に絞り、`{{zukai}} theme compare <フォルダ> <案> <案>` で、今のテーマと案を横に並べた HTML を作ります。案は `emphasis.box=tint` のように項目と値を = でつなぎ、1つの案で複数の値を変えるときは + でつなぎます。色を並べるときは `'chart.series=["#0432ff","#ff2f92","#ff2600"]'` のように JSON で書きます。並べる図は `--types=flow,bar` で絞れます。
3. 作った HTML を利用者に見せます。案ごとに、見た目の違い、検査の結果（error と warn）、資料の決まりとの食い違いを、1〜2文で添えます。おすすめの案があれば、理由と一緒に示します。
4. 系列の色の見分けにくさは、HTML の「系列の色の見え方」の行で見せます。差の数（23 未満が warn）と、どの見え方でどの色が近いかを伝えます。
5. 利用者が選んだら、その値を `tokens.json` に書き、`{{zukai}} theme check` で確かめます。
6. `rules.md` の `## 決めたこと` に、日付、決めたこと、選ばなかった案、理由を1行で書きます。例: 「2026-10-11 強調した箱は tint にした。fill は白い文字がマゼンタの上で 3.5:1 しかないため」。次にテーマを直す人が、なぜその値なのかを読めるようにするためです。
7. 利用者が、資料の決まりと違うことや、検査が error にすることを選んだときは、そのことを1回だけ伝え、利用者の選択に従います。error が残るときは、`## 決めたこと` にもそう書きます。

## 独自の型を作る

テーマの `types/<名前>/` に、次の3つのファイルを書きます。名前は英小文字で始め、組み込みの型と重ならないものにします。

1. `type.json` に、`summary`（型の説明）、`when`（使うとき）、`fields`（項目の定義）、`example`（例の仕様。`type` は書かない）を書きます。項目の `type` は `string`、`number`、`boolean`、`list`、`object` のどれかです。文字の項目には `max`（全角の字数の上限）を、配列の項目には `max`（個数の上限）と `of`（要素の定義）を必ず書きます。上限は、図からはみ出さない長さにします。
2. `figure.svg` に、図のひな形を書きます。自由な図（`{{zukai}} type free`）と同じ書き方で、`{{項目}}` を差し込みます。`{{#items}}…{{/items}}` で繰り返し（中では `{{@index}}`、`{{@n}}`）、`{{^note}}…{{/note}}` で値が無いときだけ書き、`{{= 360 - width(value, 96) / 2}}` で位置を計算します。グラデーションで塗る図形には `class="zk-grad"` を付けます。動画で一緒に現れてほしい部品は、`<g>` でまとめます。
3. 動画で決まった動き（数え上げなど）を付けるときだけ、`motion.js` を書きます。`ctx.parts`（部品）、`ctx.start`（最初の部品が現れる秒）、`ctx.frame(f)`（毎コマ `f(t, info)` を呼ぶ）、`ctx.sfx(名前, 秒)` を使い、動きは `el.animate()` か `ctx.frame` で書きます。`setTimeout` や現在時刻には頼りません。
4. `{{zukai}} theme check <フォルダ>` で、例が検査を通るかを確かめ、`{{zukai}} type <名前>` で、AI に渡る書き方を確かめます。

## 守ること

- 資料そのものは、テーマのフォルダにコピーしません。テーマをコミットしたときに、社外秘の資料がリポジトリに入らないようにするためです。「出典」には資料の名前だけを書きます。
- 資料の文章を `rules.md` に写しません。書くのは描き方のルールだけです。
- テーマを変えると、自由な図（`svg figure`）に書いた前の色は、Lint の F001 になります。利用者が既存の原稿を使い続ける場合は、そのことを伝えます。
- `{{zukai}} theme check` が値の誤り（無い項目、色でない値）で止まったら、`tokens.json` を直します。項目の一覧は、`{{zukai}} theme init` で作った `tokens.json` にあります。
