# zukai

原稿の書き方と、検査の指摘の直し方は、`zukai prompt` がリポジトリの契約ファイルから出力します。このファイルには、作業の手順だけを書きます。

`zukai` コマンドは、zukai のフォルダで `npm link` を実行すると使えます。コマンドが見つからない場合は、zukai のフォルダの CLI を node で直接実行します（例: `node /path/to/zukai/src/cli.ts doctor`）。設定の誤りで止まる場合は、`zukai doctor` の結果を利用者に伝えます。

## 手順

1. `zukai prompt` を実行し、出力された書き方に従います。図の型は一覧だけが出力されます。使う型を決めたら `zukai type <型の名前>` で書き方を確認します。
2. 既存の資料を直す依頼で HTML だけを受け取った場合は、`zukai extract <資料.html>` で原稿を取り出します。HTML や Confluence のページは直接編集しません。
3. 題材に実物の画面（画面、Web ページ、管理コンソール、ダッシュボード）がある場合は、その URL か画像を利用者に尋ね、そのセクションの図を `screenshot` にします。
4. 原稿を Markdown ファイルとして書きます。
5. 原稿に `screenshot` があり、画像がまだ無い場合は、利用者に撮影してよいかを確認してから `zukai capture <原稿.md>` を実行します。ログインが必要な画面は撮影できないので、利用者に画像を用意してもらいます。
6. `zukai lint <原稿.md> --model=<自分のモデル名>` を実行し、書き方の「検査を通す」に従って直します。2回直しても error が残る場合は、残った指摘をそのまま利用者に報告します。
7. 合格したら、共有先に合わせて書き出します。ファイルで共有する場合は `zukai build <原稿.md>` で HTML を作ります。Confluence に載せる場合は、利用者に登録してよいかを確認してから `zukai publish <原稿.md>` を実行します。初回は、設定に `confluence.spaceId` が無ければ `--space-id` が必要なので、利用者にスペース ID を尋ねます。API キーとトークンは、チャットで尋ねず、表示も記録もしません。足りないときは、利用者に `zukai login confluence` の実行を頼みます。

## ルールに従えない場合

図にできない内容で S004 を外す必要がある場合は、該当セクションに `<!-- zukai-ignore S004 理由 -->` を書きます。理由のない抑制は無効です。抑制した箇所は利用者に報告します。
